# CLV Is Two Named Metrics, and Bet Type Is Persisted at Log Time

[[De-vigged CLV]] and [[Percentage-Point CLV]] are stored in separate fields and never averaged together, and every [[Pick]] records its `bet_type` when it is logged rather than having it re-inferred from prose at resolution time.

**Context:** two independent defects had made the money numbers untrustworthy, and both were invisible because each produced a plausible-looking value rather than an error.

*CLV was two metrics in one field.* `resolve` wrote `(close_prob − entry_prob) × 100` — vig-inclusive percentage points. `backfill-clv` wrote `(fair_prob / entry_prob − 1) × 100` — a de-vigged ratio. Both landed in `clv`, and `clv_stats` averaged them into a single `avg_clv` that was published to the dashboard. The ratio form is systematically larger in magnitude, so whichever writer ran more often dominated the mean. Separately, `is_measured_clv` tested only that `closing_line` was truthy, so six picks carrying a hand-written `clv` of `0.0` beside unparseable free text (`'Mets ML +110'`, `'Spurs +6.5 -110'`) counted as Measured — 18% of the denominator, dragging the average toward zero. CONTEXT.md already called a placeholder `+0.00%` Unmeasured; the code disagreed with it.

*Bet type was never persisted.* ADR 0004 specifies classifying "using the `bet_type` field when present, inferring from bet text otherwise", but `cmd_log` never wrote the field — only 6 of 87 picks had it, all hand-added. Fragile text inference was therefore the only live classifier, and it had three holes. `classify_bet` had **no `spread` branch at all**, so a spread fell through to the moneyline path, which ignores `line_num` entirely: any spread that covered without winning outright graded a LOSS, and any favourite that won without covering graded a WIN. Game totals were anchored on `^(over|under)`, which **0 of 8 real game totals matched** — they read `"Twins @ Cubs Under 8 (game total)"` and were graded on `game_margin`, the exact ADR 0004 mis-resolution class. And `determine_outcome` compared `margin > line_num` (signed) while `needed_to_cover` and the context builders used `abs(line_num)` (unsigned) and the CLI help documented unsigned — three conventions for one field, under which **every winning underdog run line graded as a loss**.

Two smaller faults shared the same signature: `_game_result_dict` read scores with `.get("score", 0)`, so an upstream schema change would have turned every moneyline into a push and every Under into a win rather than failing; and `cmd_log` typed bets by substring, so `"rl" in bet_lower` matched the Ma**rl**ins and filed every bet against Miami as a run line.

**Considered Options:** pick one CLV metric and discard the other (loses either hold-correctness or coverage); keep one field and add a `clv_metric` discriminator column (still invites blending); store both metrics in named fields. For classification: keep inferring from text but harden the regexes; persist `bet_type` at log time and treat inference as fallback only.

**Decision:** `clv_devig` and `clv_pct_pts` are separate fields. De-vigged is preferred and is what the headline CLV statistics report, because stripping the overround stops the book's hold masquerading as edge; percentage points is the wider-coverage fallback, reported over its own denominator, because it is computable from a one-sided close. `clv` survives only as a legacy mirror of whichever is preferred-and-available. `closing_line` must parse as American odds to be stored or to count as Measured. `cmd_log` persists `bet_type` from `classify_bet`, which gains a `spread` branch and recognises matchup-style game totals by where the matchup separator sits relative to the Over/Under — a plain stat-keyword test cannot separate `"Padres @ Dodgers Under 8 runs"` from a player prop, because `runs` is itself a stat. `line_num` is **signed as the bet reads** (`+6.5` dog, `-1.5` favourite), covering when `margin + line_num > 0`. A Final game missing a score raises `MissingScoreError` and leaves the pick open instead of grading a fabricated 0-0.

**Consequences:** historical CLV was migrated with `migrate-clv-schema`, which recomputes percentage points from each pick's own `(line, closing_line)` — fully reproducible — and demotes the six unparseable ones to Unmeasured. Legacy de-vig values are identified by not reproducing under `calc_clv` and preserved into `clv_devig`, so de-vig coverage is not lost. The two metrics now disagree in a way the blended figure concealed: de-vig averages **+0.03% over 18 picks** while percentage points averages **+2.55% over 27** — the honest reading is that there is no demonstrated ability to beat the close. Reclassification moved 8 of 87 picks (4 prop→total, 3 ml→total, 1 ml→spread); no genuine player prop moved. The sign-convention change is safe because picks.json contains no true spread or run-line pick — the four `-rl` ids were the Marlins substring bug. CLV coverage remains far below the 90% CONTEXT.md requires before ROI is treated as mature, and the backfill still has no line-vintage guard, so a "close" fetched days after a game is of unknown provenance — both are open follow-ups, not addressed here.
